### C) البذرة الهندسية (الطلب الدائم الجديد)

- **TypeScript strict:** `noImplicitAny: true` (كان `false` —
  اتطبق بصفر أخطاء) + `noUnusedLocals` + `noUnusedParameters`
  (اتطلبوا 6 إصلاحات unused في 5 ملفات). `noUncheckedIndexedAccess`
  اتقاس واتأجل: ~30+ خطأ possibly-undefined في مسارات API —
  refactoring كبير يستحق جولة لوحده، مش إصلاح عاجل.
- **Logging:** `logger.ts` (R25) كان مغطي 7/9 مسارات API —
  الاتنين الناقصين اتضافوا: `/api/audit` (debug: حجم السجل +
  الكيانات) و `/api/health` (info: زمن الفحص `ms` — مؤشر بطء
  مبكر). أرقام فقط، صفر بيانات حساسة.
- **E2E:** سكريبتان جديدان في `scripts/` (تفاصيل تحت).

## ثالثا — E2E (درس الجولة)

1. **السكريبت الأول** بنى وشغّل واختبر — كل فحوصات الألوان عدّت
   (computed styles) لكن **اللوجو في هيدر الاتزان لسه قديم**!
2. **التشخيص:** عملية `bun server.js` قديمة (PID من جلسة E2E
   سابقة) كانت ماسكة البورت 3111. الـ `pkill -f "standalone/server.js"`
   مدايتش عليها (نمط الاسم مش مطابق) فالسيرفر الجديد مات بصمت
   (EADDRINUSE) والاختبارات كلمت القديم: ملفات static جديدة من
   الديسك (CSS/JS = إصلاحاتنا ظهرت) لكن HTML الصفحة من البناء
   القديم في الذاكرة (skeleton = mp-ico القديم).
3. **الدرس المسجل:** `pkill` لازم يطابق `bun server.js` نفسه،
   وبعد أي restart لازم نتأكد إن PID السيرفر الجديد هو اللي
   ماسك البورت (`ss -tlnp`)، مش الاعتماد على نجاح health-check بس.
4. **إعادة التحقق الكاملة** بعد قتل القديم: **ALL PASS** —
   - الدخول: `logo.png?v=r54` LOADED + رقعة 104×54 ✓
   - الفاتح: `brand h1` = `rgb(241,228,201)` ✓ (كان 31,41,55)
   - الاتزان الفاتح: `mp h2` فاتح + `img.mp-logo` LOADED ✓
   - الغامق (denim) سليم: ما اتكسرش حاجة ✓
   - VLM على اللقطات النهائية: «مقروء بوضوح، 10/10، اللوجو ظاهر
     في الحتتين» ✓
   - صفر أخطاء كونسول ✓
