# 08 — CODE INTELLIGENCE (نظام ملاحة الكود)

> **الطلب المؤسس (R63):** «لما الكود يبقى كبير أكيد انت ليك سعة معينة في
> القراءة وبعد كدا بتهيس… ابتكر الطريقة المثالية عشان تفضل فعالة حتى لو
> الموقع وصل جيجا» — الملف ده هو الطريقة. **اقرأه مرة واحدة في أول أي
> جلسة، وبعدها الخريطة هي اللي بتقود.**

## الفكرة في سطر واحد

**ما تقراش الكود — اقرأ فهرس الكود.** الفهرس (خريطة) صغير دايمًا
حتى لو الكود وصل جيجا، لأنه بيسجل «فين إيه» مش «إيه» — والتوليد
آلي من الكود نفسه فمستحيل يكذب أو يقدم.

## الطبقات الأربع

| الطبقة | إيه هي | فين | سعتها |
|---|---|---|---|
| **الخريطة** | فهرس آلي: كل API وجدول ووحدة وصلاحية ومين بيستخدم مين | `docs/CODE-MAP.md` | ~10KB ثابتة تقريبًا مهما كبر المشروع |
| **الرادار** | جوه الخريطة: عدّلت ملف X → إيه اللي بيعتمد عليه | قسم 5 في الخريطة | جزء من الخريطة |
| **الشريحة** | قراءة الملف المستهدف بالـ offset/limit — المنطقة المطلوبة بس | أداة القراءة نفسها | 50-150 سطر بدل 3000 |
| **الشبكة** | E2E يثبت إن التعديل ما كسرش حاجة — أعمق من أي قراءة | `scripts/e2e_rNN.sh` | زي ما الجولة بتحدد |

**القاعدة الحاسمة:** سعة القراءة بتتاكل لما تقرأ الملفات كلها.
الخريطة بتحول «أقرأ كل حاجة عشان ألاقي» إلى «أعرف المكان من الفهرس،
وأقرأ 100 سطر بس، وأثبت بالاختبار».

## الوصفة الرسمية لأي مهمة (إلزامية لكل جولة)

```
الخطوة 1 — حدد (0 دقيقة):
  افتح docs/CODE-MAP.md و Ctrl+F على الخصيصة/المسار/الجدول.
  الخريطة بتقول: الملف · السطور التقريبية · الحارس · الجداول · المستوردون.

الخطوة 2 — افهم الشريحة (1-2 دقيقة):
  اقرأ الملف المطلوب بـ offset/limit حوالين المنطقة المرتبطة بالخصيصة.
  لو محتاج أعمق: افتح الملفات المستوردة المذكورة في نفس السطر.

الخطوة 3 — رادار التأثير (نصف دقيقة):
  قبل أي تعديل: بص على قسم 5 — مين بيستورد الملف ده؟
  أي ملف مستورد = محتاج يتفحص أو يتغطى في E2E.

الخطوة 4 — عدّل:
  التعديل نفسه بالحجم الطبيعي — قواعد 07-HOW-TO-CONTINUE كلها سارية
  (صلاحيات + audit + CREATE IF NOT EXISTS + …).

الخطوة 5 — أثبت:
  tsc → البناء → E2E (سكريبت الجولة فوق مكتبة e2e_lib).

الخطوة 6 — حدّث الفهرس (إلزامي قبل الـ commit):
  bun scripts/code_map.mjs   ← بيعيد توليد الخريطة من الكود الجديد
  الـ E2E بيفحص إنها طازة (--check) — الخريطة القديمة مع كود جديد
  = خطأ أحمر في الجولة.
```

## إزاي بتفضل صح؟ (الضمانات)

1. **توليد آلي مش كتابة يدوية:** اليد بتنسى والسكريبت عمره ما ينسى.
   أي فجوة بين الكود والخريطة بتتصطاد في الـ E2E (`code_map --check`).
2. **حتمية (Deterministic):** نفس الكود = نفس الخريطة بالبايت —
   الـ diff بين جولتين بيوري التغيير الحقيقي بس، من غير ضوضاء تواريخ.
3. **صغيرة بالتصميم:** بتسجل المسارات والمفاتيح والأسماء — مش المحتوى.
   مشروع 10MB ومشروع 1GB بيطلعوا خريطة حجمها قريب من بعض.
4. **تنمو مع الكود:** أي API/جدول/وحدة جديدة بتدخل الخريطة تلقائيًا
   أول ما تتولد — من غير حد يفتكر يضيفها.

## سيناريوهات جاهزة (احفظها)

### «عايز أضيف ميزة في صفحة الإدخال»
1. قسم 3 في الخريطة → `app_entries.js` (الوحدة AppEntries) + الـ endpoints بتاعتها.
2. قسم 1 → المسار المستهدف `/entries/production` مثلًا: الملف + الحارس + الجداول.
3. عدّل → لو اتغير الـ HTML → cache-bust → E2E.

### «عايز أغير في الجداول»
1. قسم 2 → الجدول ← كل الملفات اللي بتلمسه (هي دي الـ blast radius).
2. `db.ts` للـ BOOT_SQL + BOOT_VER لو لازم إعادة بوت.
3. كل ملف مذكور في صف الجدول محتاج مراجعة.

### «عايز أعدل صلاحيات حاجة»
1. قسم 6 → المفتاح ← كل المسارات اللي بيحرسها.
2. `perms.ts` فيه القايمة المركزية (PERM_KEYS) — أي مفتاح جديد يتضاف هناك الأول.
3. الواجهة: `app_auth.js` (can/loadPerms) + الزراير المعنية.

### «الباج في الواجهة بس مش عارف فين»
1. قسم 3 → الوحدة المرتبطة بالخصيصة + الـ endpoints اللي بتندها.
2. قسم 1 → رد المسار نفسه — لو الـ API سليم، الباج في الوحدة.

## حدود النظام (صدق مع نفسك)

- **الرادار بنيوي (imports) مش سلوكي:** بيقول مين بيعتمد على مين في
  البناء، مش مين بينادي على مين وقت التشغيل بكل الفروع — الجزء ده
  بتغطيه الـ E2E + أوديت العمليات.
- **الخريطة بتقول «فين» مش «إيه»:** لو السؤال «الدالة دي بتتعامل مع
  إيه بالظبط» — دي قراءة شريحة، مش فهرس.
- **الواجهة مربوطة بجسر ctx مش imports:** علاقات الوحدات (قسم 5)
  مسجلة كنص توضيحي لأن JS الكلاينت ما بيعملش import — الدقة جاية من
  الأسماء الثابتة (MaribCloud/MaribAuth/I18N/MaribKit).

```bash
bun scripts/code_map.mjs          # توليد/تحديث الخريطة
bun scripts/code_map.mjs --check  # فحص الطزاجة (بيستخدمه الـ E2E)
```

- **أي هيكل جديد** (مجلد وحدات جديد، نوع ملف جديد): عدّل المولّد
