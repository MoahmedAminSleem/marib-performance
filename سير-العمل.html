١قصة المشروع

المشروع بدأ كلوحة Power BI بتقرأ ملفات الإكسل الشهرية للمصنع (مبيعات وإنتاج وجيوب وحضور) وتطلع مؤشرات الأداء. كان ليها موديل داتا كامل بـ 42 مقياس (measure) وعلاقات فلترة دقيقة بين الجداول. المشكلة كانت إنها محتاجة Power BI Desktop ومفيش غير جهاز واحد بيعرضها، والشركة عايزة الكل يشوفها من أي مكان.

  • المرحلة 1 — نسخة HTML أوفلاين: اتعملت نسخة ملف واحد Marib_Performance_Studio.html (حاليًا 1.8MB) بتشتغل من غير نت وبتقرأ فولدر الإكسل من الجهاز. ثيم الجينز والذهبي، 3 لغات (عربي / تركي / إنجليزي). دي كانت المرحلة اللي اتعمل فيها معظم تطوير الواجهة والرسومات.
  • المرحلة 2 — النسخة الأونلاين (الحالية): اتبنت نسخة سيرفر كاملة: تسجيل دخول متعدد المستخدمين + صلاحيات + قاعدة بيانات PostgreSQL على Neon + نشر على Vercel من الريبو الخاص. نفس اللوحة بالظبط بس الداتا على السيرفر والشركة كلها بتشوفها من لينك واحد.
  • المرحلة 3 — 2026-09-08: اتقرر إن النسخة الأوفلاين اتقاعدت خلاص — كل الشغل من دلوقتي على النسخة الأونلاين المرفوعة بس.
الزتونة: كل الحسابات والمنطق متطابقة بالبايت مع موديل Power BI الأصلي — نفس الجداول، نفس العلاقات، نفس المعادلات (مكتوبة أصلًا في public/app/app_core.js ومتعليقة "Mirrors the user's Power BI semantic model EXACTLY").

٣تدفق الداتا — من الإكسل للشاشة

  • 1) الرفع: من تابة "البيانات" جوه الموقع، بيتحدد الشهر وبيترفع ملف (أو ملفات) الإكسل بتاعة الشهر ده.
  • 2) التحليل في المتصفح: نفس محرك التحليل بتاع النسخة الأوفلاين (app_core.js) بيقرأ الشيتات الخمسة ويحوّلها لـ pack جاهز.
  • 3) المزامنة للسيرفر: marib_cloud.js يبعت الـ pack لـ POST /api/data ويتخزن على Neon.
  • 4) العرض للكل: أي حد بيفتح الموقع بيلاقي الشهر الجديد ظهر مع الباقي — وفيه سجل عمليات (audit) بيكتب مين عمل إيه وإمتى.
قاعدة مهمة: التعديلات بتاعة الجولات (كود/رسومات/ترجمات) ماتلمسش الداتا المخزنة أبدًا — الداتا بتعيش لوحدها في قاعدة Neon والكود بيتحمل فوق القديم من غير ما يمسها.

٨نظام الجولات — طريقة الشغل والتسليم

  • الجولة (R + رقم): حزمة تعديل واحدة. بتتسلم كـ ملف ZIP فيه الملفات المتغيرة بس (بنفس مساراتها في الريبو) + ملف الملفات-المتغيرة.txt (المانيفست بالـ md5) + ورقة دليل HTML بالخطوات.
  • الرفع: فك الضغط → افتح الريبو على GitHub → Add file → Upload files → اسحب الفولدرات والملفات → Commit → Vercel بينشر لوحده في دقيقة. (الملفات اللي ليها نفس الاسم والمسار بتتحول تلقائيًا فوق القديمة).
  • التراجع لو حصلت مشكلة: GitHub بيحتفظ بكل نسخة قديمة — من صفحة الملف → History → رجّع أي نسخة سابقة بنقرة.
  • التحقق بعد النشر: افتح الموقع → اعمل Refresh قوي (Ctrl+F5) → اتأكد إن التعديل ظهر.
